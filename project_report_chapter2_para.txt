CHAPTER 2: SYSTEM REQUIREMENTS AND ARCHITECTURE

2.1 SYSTEM REQUIREMENTS

The development, deployment, and testing of the Campus Complaint Management System require specific hardware and software configurations to achieve optimal operational efficiency and performance. The hardware requirements for the development and server hosting environment dictate a system powered by at least an Intel Core i3 or AMD equivalent processor running at 2.0 GHz or higher, alongside a minimum of 4 GB of random access memory, though 8 GB is highly recommended to handle the concurrent demands of the Flask web server, local database transactions, and browser testing. In terms of physical storage space, a minimum of 500 MB of free hard drive space is necessary to store the application source code files, database schemas, local backup database instances, uploaded student attachments, and other required Python project dependencies. For access on client devices, the web portal is highly optimized to run on any smartphone, tablet, laptop, or desktop computer equipped with a modern web browser and at least 2 GB of memory, dynamically fitting displays starting from a width of 320 pixels.

On the software side, the backend server executes on modern operating systems such as Windows 10 or 11, macOS, or Linux, requiring Python version 3.8 or higher. The core web server logic is built upon the Flask micro-framework and relies on specialized libraries such as PyMySQL for establishing database connections, Bcrypt for implementing secure password cryptography, Flask-Session for managing stateful user sessions, and Python-dotenv for handling configuration parameters. The database layer utilizes MySQL Community Server version 8.0.x as the primary relational database system, and includes a built-in fallback interface configured to connect automatically to local SQLite database engines for maximum service reliability. On the client side, the frontend rendering engine supports HTML5, CSS3, and ES6+ JavaScript, working seamlessly on modern web browsers including Google Chrome, Mozilla Firefox, Microsoft Edge, and Apple Safari. Developers can maintain the codebase using standard tools such as Visual Studio Code, command line terminals, and MySQL Workbench.

2.2 FRONTEND ARCHITECTURE

The frontend interface of the Campus Complaint Management System is developed using a modern glassmorphism design language, featuring clean layouts, dark gradient color schemes, semi-transparent dashboard widgets, and subtle hover animations that guide user interactions. The application layout is structured using semantic HTML5 elements to establish an accessible and logical document flow, while visual styling and grid alignments are handled using Bootstrap 5 classes to ensure complete responsive adaptability across multiple device viewport widths. One of the core presentation assets on the student and administrator dashboards is the circular resolution statistics chart, which is rendered using pure CSS conic-gradient functions that map real-time percentages dynamically without loading bulky external charting libraries. The user experience is highly interactive, utilizing vanilla JavaScript to trigger asynchronous fetch calls to backend APIs for tasks such as status edits, staff assignments, and complaint deletions. These asynchronous API calls update the Document Object Model in real-time, fading out deleted database rows, animating numerical counters, updating the CSS donut chart, and displaying toast alert overlays without reloading the webpage.

2.3 BACKEND ARCHITECTURE

The backend architecture acts as the central control layer that routes incoming client queries, enforces security rules, and performs database actions. Built using Python and the Flask framework, it handles requests by executing controller functions that render responsive templates dynamically using the Jinja2 template engine. To handle security, the backend tracks logged-in accounts using server-side session variables, verifying the role privileges of students, staff, and admins before loading restricted pages or executing modifying actions. Cryptographic password protection is achieved by hashing registration credentials using the Bcrypt library, which prevents data leaks from revealing raw passwords. The connection between Flask and the database is managed by a custom connection class using PyMySQL to interact with the local MySQL server. To guarantee maximum uptime, the backend is integrated with an automated self-healing fallback mechanism that continuously monitors the MySQL connection; if the MySQL server goes offline, the backend dynamically redirects all incoming and outgoing database queries to a local SQLite database file, allowing the campus system to remain fully operational during database server maintenance.
