2.4 EXPLANATION OF THE DATABASE SCHEMA DIAGRAM

The database schema diagram represents the physical design and structural organization of the relational database used in the Campus Complaint Management System. It outlines the specific tables, column names, data types, and logical constraints compiled on the MySQL database engine. The schema consists of 8 normalized tables designed to eliminate data redundancy and enforce referential integrity using primary keys (PK) and foreign keys (FK). The primary key columns (such as dept_id, user_id, and complaint_id) are marked with gold key icons to indicate that they uniquely identify each record in their respective tables. Foreign key columns are marked with silver key icons, representing references that link tables together to establish relationships. For example, the user_id column in the complaints table is a foreign key pointing directly to the user_id primary key in the users table, identifying which student submitted the complaint.

Referential integrity is strictly controlled using constraint options like ON DELETE CASCADE and ON DELETE SET NULL. For tables representing subordinate details—such as complaint_logs, comments, feedback, and notifications—an ON DELETE CASCADE rule is applied. This means that if a parent complaint is deleted from the complaints table, the database automatically deletes all corresponding logs, user comments, satisfaction feedback, and notification alerts to prevent orphaned records. Conversely, for structural lookups like departments and categories, an ON DELETE SET NULL constraint is applied to the complaints table. If a department or category is removed from the database, the complaints associated with them are not destroyed; instead, their department or category references are simply set to NULL, keeping the complaint record intact. Additionally, check constraints are implemented, such as verifying that rating values in the feedback table fall strictly between 1 and 5.

2.5 EXPLANATION OF THE ENTITY-RELATIONSHIP (ER) DIAGRAM

The Entity-Relationship (ER) diagram models the conceptual schema of the Campus Complaint Management System, illustrating how real-world entities interact within the system. The diagram uses standard Crow's Foot notation to represent relationships and cardinalities between different entity sets. The core entities include User (representing Students, Staff, and Admins), Department, Category, Complaint, Comment, Feedback, Notification, and Complaint Log. Each entity contains specific attributes that describe its properties, such as the Complaint entity possessing attributes for title, description, priority, and status. The connecting lines between the entity boxes represent the relationship paths, with Crow's Foot symbols at the endpoints showing the cardinality (ratios) of how the entities associate with one another.

The system relies on several one-to-many (1:N) relationships to coordinate its workflows. A single User (Student) can submit many Complaints over time, but each individual Complaint is filed by exactly one User, establishing a 1:N relationship. Similarly, a single Department can contain many Categories (e.g., the IT department handles "WiFi Issues" and "System Issues"), and a Department is responsible for handling many Complaints. When an Administrator delegates tasks, a Staff member can be assigned to manage many Complaints, but each Complaint is handled by one specific Staff officer at any given time. Furthermore, a single Complaint acts as a parent record that can accumulate many Comments (forming a dialogue thread), generate many Notification alerts, and write many entries to the Complaint Log as it moves from pending to resolved. The relationship between a Complaint and its Feedback rating is defined as one-to-one (1:1), ensuring that a student can only submit a single review for any resolved complaint.
